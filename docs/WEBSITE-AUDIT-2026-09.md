## 4. Skills Lab architecture

`cloudflare/seed-games.sql` registers 15 active activities: six goniometry, five cardiorespiratory, typing, AI Literacy Check, Reasoning Runner and Clinical Readiness Lab. The old respiratory-rate activity remains inactive without deleting historical results.

- Public learners can play without login. Standard result cards are local; no student progress save occurs in public mode.
- Anonymous public analytics are a separate Worker (`game-analytics.js` and `cloudflare/game-analytics/`); public mode does not mean zero network telemetry.
- Games calculate deterministic native scores. Shared progress code normalises/records platform scores; the Worker validates bounded payloads but does not independently replay gameplay.
- Goniometry native maximum 120 is normalised to 100; cardio and reasoning rubrics differ. Hints/AI requests do not reduce technical score. Independence uses `[100,90,80,70,60]` for increasing support requests.
- These are formative measures, not tamper-proof or clinically validated competence assessments. Existing lecturer-review flags in `docs/GAME-SCORING.md` remain applicable.
- The next-activity sequence is duplicated in `student/assets/progress-client.js` and must remain aligned with SQL registration order. Tracked continuation is withheld until a save succeeds.

## 5. Student and tracked mode

`student/assets/auth.js` derives the site root from its script URL, preserving `/TakWing/`. Production API: `https://physio-skills-api.takwing-yu.workers.dev`; localhost defaults to port 8787 or an explicit runtime override. Sessions are held in `sessionStorage`, sent as Bearer tokens, and cleared on 401/logout. Login leads to the dashboard. Dashboard and `?tracked=1` activities require `/api/me`; dashboard fetches catalogue/progress and adds `tracked=1` to activity links.

The Worker hashes passwords using salted PBKDF2, stores hashed session identifiers, binds SQL parameters, gates data by the authenticated session, and restricts production CORS to the portfolio origin. Standard results use UUID deduplication and an atomic insert/summary trigger; best/latest values, bounded history and legacy scales are preserved. The result client freezes a completion payload, reuses the UUID on retry and retains it in memory during reauthentication. Navigation/refresh can discard an unsaved result.

Language-link interception preserves tracked mode. Dashboard/history, completion text and much tutor UI remain English. A separate accessibility/localisation review is needed before describing these as fully multilingual.

The audit ran backend isolation/retry/migration tests and local unauthenticated browser gates. It did not create credentials, log into a real student account, complete production attempts, migrate D1 or redeploy the Worker. Prior authenticated end-to-end evidence is recorded in `docs/FUNCTIONAL-REVIEW-2026-09.md`; it is historical, not a fresh Phase 1 result.

## 6. AI Tutor

The implementation and `docs/AI-TUTOR-GAME-MAP.md` agree:

- Eleven clinical games have configured context adapters; typing and the three other activities do not have a clinical tutor.
- Requires tracked mode, a configured route and successful authentication. Vendor code is loaded only after an explicit help request.
- `skills-tutor-context.js` builds a bounded in-memory game summary; `zapier-skills-tutor.js` owns the panel and vendor integration; `skills-tutor.css` handles its layout.
- The student copies the current attempt and pastes it into the Zapier inline chat. Opening the tutor does **not** automatically send context. Readiness messages are not evidence of model receipt.
- The tutor does not re-score gameplay. AI requests measure help-opening requests, not observed replies/messages; no transcript is saved to D1.
- Optional result forwarding is a separate post-save webhook, described in `docs/ZAPIER-RESULTS.md`. It is best-effort and D1 remains authoritative. Repository code does not prove a Zap is configured.
- Third-party retention, institutional approval, external delivery and quality of future replies remain outside this audit's verification. No chat message or email was sent.

## 7. Navigation, paths and interaction

Main navigation: Home, About, Research, Teaching, Writing, Media, Resources, Collaborate with me. Search, language and theme controls accompany it. Student access is surfaced through Resources/Skills Lab rather than replacing the portfolio navigation. Games have their own smaller navigation shells.

Generated relative links and root helpers preserve the Pages base path. Static checks cover local file and cross-page fragment references; an additional scan covered same-page fragments and CSS `url()` paths, which the existing structural script does not fully cover. No broken targets were found. The 184 published sitemap URLs all returned HTTP 200 in a read-only HEAD scan. External editorial link destinations were not exhaustively checked.

Mobile navigation uses `inert`, `aria-expanded`, Escape handling and a focus loop. Search restores focus on Escape but lacks equivalent Tab containment: a fresh local check moved focus outside the open search dialog to the mascot button. This is a confirmed accessibility issue deferred to the appropriate phase.

## 8. Language, theme and reveal behaviour

- Portfolio routes: English at root, Traditional Chinese under `zh-hant/`, Simplified Chinese under `zh-hans/`; canonical and hreflang metadata are generated.
- Standalone goniometry/typing activities use `?lang=...` and their own dictionaries; generated AI Literacy/Runner/Readiness use locale directories.
- The Cardiorespiratory hub advertises language alternates but `?lang=zh-hant` still renders English. Do not confuse alternate metadata with translated content. Full clinical translation needs author review.
- Shared theme key: `portfolio-theme-v2`, with system preference fallback. Several standalone clients safely catch storage failures; `script.js` reads/writes localStorage without a guard. A blocked-storage test produced `SecurityError` and left search uninitialised. Documented, not changed in Phase 1.
- Reveal content is visible by default and becomes animated after `reveal-ready` is added. IntersectionObserver reveals each item once; reduced-motion mode skips this path. An unsupported IntersectionObserver could leave reveal-ready content hidden; no fallback check is present.

## 10. Technical debt and performance

- `generate-site.mjs` is about 249 kB; `article-content.mjs` about 356 kB. These are build inputs, not themselves browser transfer costs. Multiple arrays/maps require coordinated edits.
- `academic.css` is about 73 kB plus 14 kB `styles.css`, with further component sheets and historical overrides. Consolidation should follow visual regression coverage rather than blind deletion.
- English search payload is approximately 247 kB inline / 250 kB JSON, uncompressed. Inline indexing is loaded on ordinary portfolio pages even when search is unused; assess lazy loading only in a later phase.
- `assets/` totals approximately 55.55 MiB across 105 files, including source PNGs and optimised variants. Total repository size is not page transfer size. The two currently served Blog II PNGs are 2,112,632 and 1,852,966 bytes; image optimisation is a concrete later opportunity. No assets were removed.
- Google Fonts requests several Latin/Chinese font families. Measure real transfer/LCP/CLS with realistic network conditions before setting performance budgets; no Lighthouse score is claimed here.
- `.github/workflows/regenerate-site.yml` uses a selective input filter; authoring guidance has stale map names/counts. Some implementation documents retain old pre-deployment text below newer deployment notes. Treat dated sections as history, not live status.
- Browser tests assume installed Chrome, a discoverable Playwright module and, for authenticated native-game tests, local Worker/isolated D1 plus private existing test credentials. Avoid running those scripts against production.
